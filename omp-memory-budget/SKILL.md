# Project memory budget

Use when injected project memory exceeds its budget or diary entries crowd out doctrine. Outcome: meaningful retained facts fit below the verified cap with headroom.

Do the smallest useful thing: consolidate only the overflowing project's necessary entries; do not reorganize all memory or create a new maintenance system.

## Scope and stop boundary

Target `learned.md` only; count other injected inputs without editing them. On-demand `MEMORY.md` is not a mandatory edit or token-saving lever. Leave existing archives, live configuration and unrelated files unchanged. Justify any additional memory-file edit beforehand. Do not default to raising the cap. Stop if the active project, injection behavior or current source cannot be established.

## Procedure

1. Identify the active project memory directory and installed version with `omp --version`. Read `omp config get memories.summaryInjectionTokenLimit`; verify that version's injection implementation for shared inputs, ordering, wrappers and truncation. Do not assume defaults or whole-file lesson injection.
2. Measure combined injected inputs, including `memory_summary.md` where applicable. Use the actual backend tokenizer/accounting path; record its identity, counts, cap and headroom. Otherwise label approximations as estimates, state uncertainty and leave budget verification incomplete.
3. Read complete entries. Retain durable constraints, corrections and doctrine; merge duplicates without weakening conditions. Remove diary state only after confirming its authoritative tracker contains it. Drop duplicated procedures only after reading the covering skill and confirming equivalent coverage. Record relocation pointers. Dates and hashes can be durable facts: judge meaning, never blanket-delete by regex.
4. Preserve source language, entry format, encoding, line endings and final-newline convention. Immediately before rewriting, reread the source and create a SHA-256-verified backup of those exact bytes. Concurrent autolearn invalidates snapshots: compare current source with the backup before replacement; if changed, stop, reconcile new entries and refresh the backup rather than overwriting them.
5. Rewrite only necessary entries. Reread output and current injected inputs. Verify meaningful facts and qualifications survived, relocation targets contain the information, formatting is preserved and combined tokens remain below the cap with explicit headroom for regeneration and autolearn. Recheck after subsequent captures; do not claim savings from already-truncated content.

Report edited and backup paths, before/after hashes and entry counts, preserved-fact checks, relocation evidence, tokenizer/counts, cap and headroom.
